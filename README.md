## Step 1: Set Up the Backend

### Prerequisites
- Python 3.10+ installed
- Your existing `app_core.py` file

### Instructions

```bash
cd backend

# Copy your existing app_core.py into the backend folder
cp /path/to/your/app_core.py .

# (Optional) Copy app_version.py if you have one
# cp /path/to/your/app_version.py .

# Install Python dependencies
pip install -r requirements.txt

# Start the API server
python api_server.py
```

The backend will start at **http://localhost:8000**.

You can verify it works by opening:
- http://localhost:8000/health → shows `{"status":"ok","version":"..."}`
- http://localhost:8000/v1/websites → shows your configured websites
- http://localhost:8000/docs → interactive Swagger API docs (auto-generated by FastAPI)

### What api_server.py does
It wraps every method in your existing `ScraperBackend` class as HTTP endpoints.
Your `tender_manager.db` database is used directly — no migration needed.

## Step 2: Set Up the Frontend

### Prerequisites
- Node.js 18+ installed (download from https://nodejs.org)

### Instructions

```bash
cd frontend

# Install JavaScript dependencies
npm install

# Start the dev server
npm run dev
```

The frontend will start at **http://localhost:5173**.

Open it in your browser — you should see the BidManager dashboard showing
live data from your SQLite database.

### How it works
- Vite dev server runs at port 5173
- All `/v1/*` API calls are proxied to your backend at port 8000
- React Query handles data fetching, caching, and refetching
- Changes to `.tsx` files hot-reload instantly

---

## Step 3: Use It

### If you have existing data (tender_manager.db):
1. Make sure your `tender_manager.db` is in the same folder as `api_server.py`
   (or configure `app_paths.json` to point to it)
2. Open http://localhost:5173
3. Dashboard shows your existing tenders, projects, and stats
4. Online Tenders page shows your scraped tender data

### If starting fresh:
1. Open http://localhost:5173
2. Go to Online Tenders → the website dropdown shows MahaTenders/ETenders/Eprocure
3. Use "Fetch Organizations" → "Get Tenders" to start scraping
   (Note: scraping requires Selenium/Firefox — same as your desktop app)

## Desktop App (Optional)

You can package everything into a native desktop app that opens in its own
window — no browser needed.

### Quick test (no packaging):

```bash
# One-command local desktop run
run_desktop.bat
```

This starts the FastAPI backend and opens the React app in a native OS window.
If WebView2 is unstable on your machine, run:
`python desktop_app.py --browser`

### Build distributable .exe (Windows):

```bash
# Make sure app_core.py is in backend/
build_desktop.bat
```

Or manually:
```bash
pip install pyinstaller
cd frontend && npm run build && cd ..
pyinstaller desktop_app.spec --noconfirm
```

Output: `dist/BidManager/BidManager.exe`  
(build cache also stored in `C:\BidManagerBuild\dist\BidManager\BidManager.exe`)

Double-click it — it launches the full app in a native window, no Python
or Node.js needed on the target machine.

If the native window crashes on startup (WebView2 issue), launch:
`BidManager.exe --browser`
or force native mode explicitly with:
`BidManager.exe --native`

### Build installer (`Setup.exe`) with shortcuts (Windows)

This creates an install wizard and installs to a writable per-user location:
`%LocalAppData%\BidManager` (better for SQLite/download writes than Program Files).

Run:
`build_installer.bat`

Or with a custom version:
`build_installer.bat 1.2.3`

Installer output:
`dist/installer/BidManager-Setup-<version>.exe`

Prerequisite:
Inno Setup 6 (compiler `ISCC.exe`) installed.

### How it works

```
┌─────────────────────────────────────────────┐
│              BidManager.exe                  │
│                                              │
│   ┌──────────────┐   ┌───────────────────┐  │
│   │  PyWebView    │   │  FastAPI + React  │  │
│   │  (native      │──→│  (localhost:8100) │  │
│   │   window)     │   │                   │  │
│   │              │   │  API + static     │  │
│   │  Uses OS     │   │  files served     │  │
│   │  WebView2    │   │  from same port   │  │
│   └──────────────┘   └───────────────────┘  │
└─────────────────────────────────────────────┘
```

- `desktop_app.py` finds a free port, starts FastAPI in a background thread
- FastAPI serves both the REST API (`/v1/*`) and the React build (static files)
- PyWebView opens a native window pointing to `localhost:<port>`
- Everything runs in a single process — close the window and it all stops

## Architecture

```
┌──────────────┐     HTTP/JSON      ┌──────────────────┐
│   Browser     │ ←──────────────→  │  FastAPI Server   │
│   (React)     │   localhost:5173   │  (api_server.py)  │
│               │   proxied to :8000 │                   │
│  - Dashboard  │                    │  - REST endpoints │
│  - Tenders    │                    │  - Wraps app_core │
│  - Projects   │                    │  - SQLite DB      │
│  - Settings   │                    │  - Async jobs     │
└──────────────┘                    └──────────────────┘
```

The frontend talks to the backend via REST API.
The backend uses your existing `app_core.py` code unchanged.
All scraping, captcha handling, and file downloads happen server-side.

## Deploy Backend To Google Cloud Run

The Cloud Run container lives in `backend/`, so Google Cloud builds and deploys
only the FastAPI backend processing code. The frontend, Electron wrapper, and
desktop build files are not part of the Cloud Run service.

### First deploy

Install the Google Cloud CLI, sign in, then run from the repo root:

```bash
gcloud auth login
gcloud config set project YOUR_PROJECT_ID
gcloud services enable run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com
gcloud run deploy bidmanager-backend --source backend --region asia-south1 --allow-unauthenticated --memory 2Gi --cpu 1 --timeout 900 --concurrency 10 --max-instances 1 --no-cpu-throttling --set-env-vars BIDMANAGER_CORS_ORIGINS=http://localhost:5173\,bidmanager://app,BIDMANAGER_HEADLESS=true
```

After deployment, test `https://your-cloud-run-url/health`.

### Connect the frontend to Cloud Run

Set `VITE_API_BASE_URL=https://your-cloud-run-url` in `frontend/.env`, then run the frontend build or development server.

When the frontend is deployed online, update CORS:

```bash
gcloud run services update bidmanager-backend --region asia-south1 --max-instances 1 --no-cpu-throttling --set-env-vars BIDMANAGER_CORS_ORIGINS=https://your-frontend-domain.com\,http://localhost:5173\,bidmanager://app,BIDMANAGER_HEADLESS=true
```

Cloud Run containers have disposable local filesystems. For permanent online storage, use a managed database and Cloud Storage.

CAPTCHA images are produced by headless Firefox in Cloud Run. The CAPTCHA provider, model, endpoint, and key are configurable through Settings or the `CAPTCHA_AI_PROVIDER`, `CAPTCHA_AI_MODEL`, `CAPTCHA_AI_ENDPOINT`, and `CAPTCHA_AI_API_KEY` environment variables. Supported providers are `manual`, `gemini`, and `openai-compatible`. The desktop polls the cloud `/v1/captcha/pending` endpoint and submits manual answers to `/v1/captcha/respond` whenever AI is disabled or fails. Keep `max-instances=1` because jobs and CAPTCHA queues currently live in process memory, and keep CPU throttling disabled so background scraper threads continue after the start-job HTTP request returns.

For Cloud Run AI solving, store the chosen provider key in Secret Manager and map it to `CAPTCHA_AI_API_KEY`. Set `CAPTCHA_AI_PROVIDER` and `CAPTCHA_AI_MODEL`; also set `CAPTCHA_AI_ENDPOINT` when using an OpenAI-compatible API. Do not store production cloud keys in the desktop settings database.

## Troubleshooting

### "Backend offline" message in the UI
- Make sure `python api_server.py` is running in a separate terminal
- Check that port 8000 is not taken by another app

### Import errors when starting the backend
- Make sure `app_core.py` is in the `backend/` folder
- The scraper dependencies (Selenium, etc.) are optional — the API
  will start without them, but scraping jobs will fail

### Empty tender list
- Your database might be empty — run fetch organizations + fetch tenders
- Or copy your existing `tender_manager.db` to the backend folder

### CORS errors in browser console
- The API server already allows localhost:5173
- If you changed the frontend port, update the CORS origins in api_server.py
